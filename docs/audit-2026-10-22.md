## 4. Things Done Well

1. **Repository interface isolation** — `QuestionRepository` in `db/repository.ts` abstracts all Dexie calls behind a typed interface. Adding a `supabaseRepository` implementing the same interface will require zero UI changes — exactly what CLAUDE.md requires for Phase 2.
2. **Zod-validated importer** — `validateImport()` uses Zod for strict schema enforcement and forces `status: 'unverified'` on all imports regardless of input value, correctly preventing unverified content from appearing as verified.
3. **TOS data integrity** — `validation.test.ts` machine-verifies that exam weights sum to 100%, each subject has exactly 100 items, and all 20 sample questions reference real competency IDs. Domain correctness is tested, not assumed.
4. **Strict TypeScript** — No `any` in production code; Dexie table types are fully parameterized; Pinia stores expose narrow public APIs; the only casts are the router-param workaround (`as unknown as { id: string }`) which is documented.
5. **Dexie schema versioning** — Five versioned migrations (v1–v5) with additive-only `stores()` calls means IndexedDB upgrades are non-destructive and the app can be updated without data loss.
